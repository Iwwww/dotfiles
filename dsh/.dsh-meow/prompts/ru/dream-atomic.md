【Память этой группы】 выше — это весь объём управления этого окна: то, что ты сам создал, и то, что смотрел, когда в этом окне подставлялась/искалась/читалась (memory_read) запись. Дальше этого диапазона не заходи — не пытайся вспомнить записи «видел, но не в списке».
Есть ли что, по твоему мнению, стоит разобрать/обновить? Если есть — обнови.

## Как судить, что обновлять — пройдись по списку выше построчно; сейчас тебе кажется:
1. Есть ли записи, записанные тогда с ошибкой или односторонне, устаревшие, с информацией, требующей обновления, с изменённым решением пользователя, с новым прогрессом? → Вовремя обнови содержимое; информация в памяти должна соответствовать последнему состоянию прогресса проекта.
2. Есть ли опровергнутое, изменённое, доказавшееся недействительным проектирование и информация? → Поставь status=archived для архива, ни в коем случае не оставляй active или stale. stale означает только «завершено» (todo сделано, тема достигла цели), а не «отменено»; оставленные в базе старые, уже заменённые решения и выводы лишь вводят в заблуждение будущие сессии.
3. Есть ли завершённые записи todo? → Поставь status = stale (считается done).
4. Есть ли неверные, слишком мелкие, сейчас тебе вообще неважные записи? → Поставь status=archived.
5. Был ли когда-то bug, который теперь исправлен, был ли lesson, который больше не актуален? → Измени содержимое или поставь status=archived.
6. Обнаружил ли взаимопротиворечащие записи? → Исправь по тем фактам, которые знаешь. Оставь свежий факт, старую версию поставь status=archived.
7. Сейчас, оглядываясь, правильно ли выставлен importance у записей (проверь по правилам importance системы памяти)? Внимание: не выставляй высоко важность без оснований — важность рабочих записей о прогрессе обычно 1, максимум 2; только для серьёзного можно 3; найденное завышенное понизь.
8. Есть ли слишком длинная запись с слишком много информации? → Разбей на несколько; можно поправить через update или создать новую через remember.
9. Точны ли ключевые слова записей? → Если точны — не трогай параметр keywords; если кажется неточным — обнови через параметр keywords в memory_update. Когда prompt пользователя попадает в ключевые слова записи, она извлекается. Поэтому думай в обратную сторону: «При упоминании каких слов в prompt пользователя я хочу, чтобы эта запись нашлась?» — это критерий записи ключевых слов. Не используй имя проекта как ключевое слово, а информацию, более специфичную для самой записи. Приоритет — ключевые сущности, семантические центры, имена собственные. 8–13 штук.
10. Точна ли метка project? Не должна ли какая информация быть глобальной, но ошибочно помечена project? Тогда метку project убрать. Не есть ли какая информация явно относящаяся к какому-то project, но без метки project? Тогда добавить.
11. Учиться надо и думать: абстрагировать и обобщать больше:
- Это отличный момент подвести под общий каркас обобщения — посмотри, есть ли универсальные правила, которые стоит выделить и зафиксировать? Можно добавить новую запись.
- Сейчас ты можешь понимать некоторые записи лучше и глубже — можешь их обновить.
12. Посмотри на содержимое первого inject: все ли это важно сейчас? Нужно ли вводить в каждом session на первом раунде? Если есть неважное — понизь importance или перенеси в другой уровень (например, fact).
В первый раунд вводится только: soul (сам ИИ) / user (предпочтения пользователя) / глобальные rules (importance≥2). Чтобы попасть в первый раунд: глобальные правила → перенести в rules и importance≥2 (в project «Глобально»); о пользователе → в user; о самом ИИ → в soul.
13. memory_project показывает записи уровня project (завершённые todo — только последние 5) + проектные rules; проверки выше тоже применимы (todo завершён — stale, устаревшее — archived, метки project точны).

Пояснения:
Важно: обязательно проверь построчно, заархивируй устаревшую память и вводящую в заблуждение, либо поправь — из двух предпочитай архив.
Для записи, которую считаешь очень важной, если не уверен, каков фактический исход, — можешь прямо открыть файлы проекта и проверить. Только для очень важных записей.
По завершении просто ответь «эта группа обработана» и не вызывай другие инструменты.

За один раунд можно вызвать несколько инструментов; постарайся выполнить все вызовы для этой задачи в одном ответе.
